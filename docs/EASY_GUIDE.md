# 스마트안경 점검 도우미 — 사용법 · 시연 순서 · 유지보수

## 1. 한 장 사용법 (감독위원용)

| 단계 | 할 일 | 화면에서 누를 것 |
| --- | --- | --- |
| 1. 준비 | 휴대전화 끄기, 전자기기 걷기, 허용 장비 확인 | 3가지를 하나씩 눌러 체크 → **다음** |
| 2. 기기 찾기 | 걷은 뒤에도 켜져 있는 블루투스 기기 확인 | **안경 종류만 찾기** → 목록 창에서 기기 하나 고르고 ‘페어링’ |
| 3. 안경 보기 | 의심되는 안경을 교탁에 놓고 살펴보기 | **카메라로 살펴보기** 또는 **도감과 비교하기** |
| 4. 기록 | 확인한 사실을 남기기 | **기록지 인쇄 · PDF 저장** 또는 **엑셀용 파일 받기** |

### 카드 색의 뜻

| 색 | 뜻 | 할 일 |
| --- | --- | --- |
| 빨강 | 스마트안경일 수 있음 (이름 단서) | 기관 절차에 따라 안경을 교탁에 놓게 하고 3단계에서 확인 |
| 노랑 | 어떤 기기인지 모름 | 감독 장비인지 확인, 아니면 주변 살피기 |
| 회색 | 안경이 아닌 전자기기 이름 | 전원·수거 여부 확인 |
| 초록 | 확인 끝 | 없음 |

### 이름을 바꾼 기기는 어떻게 찾나

‘안경 종류만 찾기’는 **이름**과 함께 **제조사 번호·서비스 번호**도 봅니다. 이 번호는 기기 이름을 바꿔도 그대로라서, 이름이 달라도 목록 창에 뜹니다. 이렇게 고른 기기는 빨강 카드에 **“안경 제조사 신호와 같아요”** 라고 표시됩니다.

| 번호 | 종류 | 대상 | 겹칠 수 있는 것 |
| --- | --- | --- | --- |
| `0x01AB` | 제조사 | Meta (Ray-Ban Meta 등) | Meta의 다른 제품(Quest 등) |
| `0x058E` | 제조사 | Meta Platforms Technologies | 위와 같음 |
| `0x0D53` | 제조사 | Luxottica (Ray-Ban Meta, Oakley Meta) | Luxottica의 다른 블루투스 제품 |
| `0x03C2` | 제조사 | Snap (Spectacles) | Snap의 다른 블루투스 제품 |
| `0xFD5F` | 서비스 | Meta(Oculus) 서비스 | Meta의 VR 기기 |
| `0x9100` | 서비스 | Rokid Glasses (AI 안경) | 공식 등록 번호가 아니라 우연히 같은 번호를 쓰는 기기 |
| `7905fff0-b5ce-4e99-a40f-4b1e122d00d0` | 서비스 | HeyCyan 앱 계열 보급형 카메라 안경 | 출처 1곳 |

- **일부러 뺀 번호:** `0x05D6`(Jieli). 범용 칩 제조사라 저가 이어폰·스피커가 대량으로 걸립니다.
- **Rokid:** 서비스 번호 `0x9100`과 이름(“Rokid”가 들어가거나 “Glasses”로 시작)으로 찾습니다. Rokid 개발 자료 3곳(개발자 블로그, 커뮤니티 문서, 개발 후기)의 스캔 예제가 같은 값을 씁니다. 다만 그 예제들은 **안경을 페어링 모드로 둔 상태**에서 찾는 흐름이라, 평소 착용 중에도 신호가 나오는지는 확인되지 않았습니다.
- **번호가 없는 기종:** Even G1, XREAL, HUAWEI, Mijia 등은 공개된 근거를 찾지 못해 이름으로만 찾습니다.
- **출처:** 공개 프로젝트 Nearby Glasses, SquachWatch, ZuckOff, banrays와 Rokid 개발 자료가 공개한 값입니다. **이 도구에서 실기기로 직접 검증한 값이 아닙니다.** 목록과 출처 주소는 `src/lib/glasses-signals.ts`에 있습니다.
- **그래도 못 찾는 경우:** 한 공개 분석(banrays)에 따르면 Ray-Ban Meta는 전원을 켤 때와 페어링할 때만 신호가 잡혔고, 휴대전화와 연결해 쓰는 중에는 잡히지 않았습니다. 번호 단서가 있어도 **눈으로 하는 확인이 기본**입니다.

### Rokid 등 화면이 있는 안경: 쓰는 모습으로 보는 단서

도감 화면 위쪽의 **“쓰는 모습으로 보는 단서”** 와 **Rokid Glasses** 카드에 같은 내용이 있습니다.

| 볼 곳 | 단서 |
| --- | --- |
| 시선 | 문제지를 정면에 두고 일정한 간격으로 멈춰 보는 동작이 되풀이되는지 |
| 렌즈 | 안쪽에 초록빛 글자나 윤곽이 비치는지 (각도에 따라 희미함) |
| 안경다리 | 자주 만지거나 접었다 펴는지, 오른쪽 다리 버튼·다리 끝 충전 단자 |
| 앞면 | 한쪽 끝(착용자 왼쪽)의 작은 카메라 |
| 주변 | 켜진 휴대전화가 숨겨져 있지 않은지 (안경은 대개 휴대전화와 연결해 씀) |

- 공개 리뷰와 온라인에 올라온 문제풀이 앱 소개 글을 바탕으로 정리한 참고 단서이며, 실기기로 확인한 내용이 아닙니다.
- 이 행동만으로 부정행위를 판단하지 않습니다. **휴대전화 수거 확인이 가장 중요한 예방책**입니다.

### 어떤 기기로 여나

| 기기 | 브라우저 | 기기 찾기(2단계) | 안경 보기·기록 |
| --- | --- | --- | --- |
| 안드로이드 휴대전화 | Chrome 앱 | 가능 | 가능 |
| 윈도우·맥 PC | Chrome 또는 Edge | 가능 (블루투스 필요) | 가능 |
| 아이폰·아이패드 | Safari | **불가** | 가능 |

카카오톡·네이버 안에서 열렸다면 주소를 복사해 Chrome 앱에 붙여 넣으세요.

## 2. 시연 순서 (약 1분, 블루투스·안경 없이)

첫 화면의 **시연으로 둘러보기**를 누르거나, 주소 뒤에 `?demo=1`을 붙여 엽니다. PC·아이폰 어디서나 됩니다.

**화면 위 노란 띠가 다음에 누를 곳을 알려 주고, 그 버튼에 노란 테두리가 깜빡입니다.** 띠의 안내만 따라 누르면 됩니다.

1. 준비 3가지를 하나씩 누르고 **다음**
2. **안경 종류만 찾기** → 빨강 카드 3장 (Ray-Ban Meta, Rokid Glasses, 이름을 바꾼 기기)
3. **모든 기기 보기** → 노랑·회색 카드 추가
4. 카드의 버튼을 눌러 색이 바뀌는 것 확인 → **다음**
5. **도감과 비교하기** → “쓰는 모습으로 보는 단서”와 기종 카드 확인 → **다음**
6. **기록지 인쇄 · PDF 저장** (“시연용 예시”라고 찍힙니다)
7. **시연 끝내기** (시연 기록은 남지 않습니다)

직원에게 알릴 때는 첫 화면의 **동료에게 주소 보내기**를 누르면 됩니다.

### 시연 때 같이 말씀드릴 점

- 화면에 나오는 기기는 **가상 예시**입니다. 실제 탐지 결과가 아닙니다.
- 실제 현장에서는 목록 창에서 **고른 기기만** 기록됩니다. 교실 전체 자동 탐지가 아닙니다.
- 실제 스마트안경으로 정확도를 검증하지 않은 시제품입니다.

## 3. 체크리스트

### 시험 전날

- [ ] 쓸 기기에서 주소를 한 번 열어 본다 (인터넷 연결 상태)
- [ ] 안드로이드는 Chrome으로 열리는지 확인한다
- [ ] 블루투스·카메라 권한을 허용한다
- [ ] 시연 모드로 4단계를 한 번 눌러 본다

### 시험 당일

- [ ] 준비 3가지를 체크한다
- [ ] 기기 찾기는 수거가 끝난 뒤에 한다
- [ ] 빨강 카드는 기관 절차에 따라 실물을 확인한다
- [ ] 기록지를 인쇄하거나 파일로 받는다
- [ ] 끝나면 ‘새 점검 시작’으로 기록을 지운다

## 4. 유지보수 (후임자용)

### 파일 구조

| 파일 | 역할 | 고쳐도 되나 |
| --- | --- | --- |
| `src/lib/easy.ts` | 카드 문구, 엑셀용 CSV, 자동 저장 검사 | 가능 (문구는 여기서) |
| `src/easy.css` | 쉬운 화면 모양, 인쇄 기록지 모양 | 가능 |
| `src/main.ts` 의 “쉬운 화면” 구역 | 단계 이동, 시연, 기록지 | 가능 (주의) |
| `src/lib/device-hints.ts` | 기기 이름으로 안경 후보를 가르는 규칙 (원본) | 실기기로 확인한 이름만 추가 |
| `src/lib/bluetooth-scan.ts` | ‘안경 종류만 찾기’에 쓰는 이름 목록 (원본) | 위와 같이 |
| `tests/easy.test.ts`, `tests/e2e/easy.spec.ts` | 쉬운 화면 테스트 | 기능을 바꾸면 같이 수정 |

### 자주 하는 수정

| 하고 싶은 일 | 고칠 곳 |
| --- | --- |
| 카드 설명 문구 바꾸기 | `src/lib/easy.ts` 의 `easyCard` |
| 준비 3가지 이름 바꾸기 | `src/lib/easy.ts` 의 `PREP_LABELS` (기록지·CSV용), 화면 글자는 `src/main.ts` 의 `preflight-grid` |
| 제조사·서비스 번호 추가·삭제 | `src/lib/glasses-signals.ts` 의 `GLASSES_SIGNALS` (출처 주소 필수) |
| 새 안경 기종 이름 추가 | `device-hints.ts` 의 `glassesNames` + `bluetooth-scan.ts` 의 `namePrefixes` (둘 다) |
| 기록지 양식 바꾸기 | `src/main.ts` 의 `buildSheet`, 모양은 `src/easy.css` 의 `@media print` |

### 올리는 방법 (GitHub Pages)

1. 고친 뒤 `npm test`, `npm run build` 가 통과하는지 확인합니다.
2. `main` 브랜치에 올리면 GitHub Actions가 테스트 후 자동으로 배포합니다.
3. 저장소 Settings → Pages → Source 가 **GitHub Actions** 여야 합니다.

### 문제가 생기면

| 증상 | 원인 | 해결 |
| --- | --- | --- |
| 찾기 버튼이 눌리지 않음 | 준비 3가지 미체크, 또는 지원하지 않는 브라우저 | 1단계 체크, 안드로이드 Chrome·PC Chrome/Edge로 열기 |
| 목록 창이 비어 있음 | 이름이 다르거나 전원이 꺼진 기기 | ‘모든 기기 보기’로 다시, 눈으로 확인 |
| 엑셀에서 한글이 깨짐 | 다른 프로그램으로 다시 저장함 | 받은 파일을 그대로 엑셀로 열기 (UTF-8 BOM 포함) |
| 예전 기록이 계속 보임 | 자동 저장 | 4단계의 ‘새 점검 시작’ |
| 배포가 안 됨 | Actions 테스트 실패 | 저장소 Actions 탭에서 실패한 단계 확인 |

## 5. 확인 필요 사항

| 항목 | 이유 |
| --- | --- |
| 시험장에서 수험자 주변 기기를 블루투스로 확인해도 되는 근거 | 공단 공식 절차가 아니므로 본부·소관 부서 검토 필요 |
| 실제 스마트안경에서의 탐지 여부 | 실기기 검증 없음 (원본 포함) |
| 제조사·서비스 번호의 정확성 | 공개 프로젝트 값을 모은 것. Bluetooth SIG 원문·실기기 대조 필요 |
| 아이폰(Safari)·실제 안드로이드 기기 동작 | 이 수정본은 PC용 Chrome 자동 테스트로만 확인 |
